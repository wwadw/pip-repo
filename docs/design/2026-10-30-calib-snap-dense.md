# calib-snap 稠密采集模式设计

日期：2026-10-30

状态：已实现，软件验证完成，待实机验收

## 目标与前提

增加 `--capture-mode dense`。用户调整好采集位置后，按一次保存键启动一轮点云累加；满足指定帧数或时长后，保存一张图像和一个合并后的 PCD。

本设计以累加期间雷达、相机、标定板及需要参与标定的场景保持静止为前提。多帧点云在同一坐标系内直接合并；首版不包含运动补偿、ICP、坐标变换或体素降采样。累加的目标是保留多次观测，不承诺每个新增点都提供新的空间覆盖。

每一轮独立开始、结束和清空。完成后等待下一次按键，方便用户移动标定板或切换采集位置。

## 现有流程与方案选择

变更前，`code/calib_snap/calib_snap.py` 的 `_on_pointcloud()` 只更新 `_latest_pointcloud`；`save_capture()` 在按键时复制当前图像，检查最近一帧点云的年龄，再保存配对文件。程序同时支持 RTSP、本地摄像头和 ROS 图像话题。

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| 按键启动一轮累加，推荐 | 按键后接收新点云，达到目标自动保存 | 起止明确，切换采集位置后不会带入上一轮数据 |
| 持续维护滑动窗口 | 始终保留最近若干帧，按键立即保存窗口 | 保存快，但窗口可能含有刚才移动设备或标定板时的数据 |
| 启动后无限累加 | 程序运行期间持续增长，手动结束 | 结束条件、内存占用和不同采集位置的数据归属不清晰 |

采用第一种方案。已有 `auto`、`paired`、`image` 的默认选择规则继续使用；稠密模式需要显式指定。

## 命令行参数

| 参数 | 默认值 | 规则 |
| --- | --- | --- |
| `--capture-mode dense` | 原有 `auto` | 启用稠密配对采集，必须提供 `--pointcloud-topic` |
| `--accumulate-frames N` | 未设置 | 正整数，收到 N 帧通过接收校验的非空点云后结束 |
| `--accumulate-seconds T` | 未设置 | 有限正数，从按下保存键开始计时，到 T 秒结束 |
| `--accumulate-timeout T` | `5.0` | 有限正数，等待首帧或相邻两帧可接收点云的最长间隔 |
| `--accumulate-max-mb M` | `256` | 正整数，原始点云 `data` 缓存上限，单位 MiB，即 `1024 * 1024` 字节 |
| `--cancel-key KEY` | `c` | 稠密模式下取消当前尚未进入写盘阶段的轮次 |

稠密模式必须在 `--accumulate-frames` 和 `--accumulate-seconds` 中选择一个，不设隐含的累加数量，同时提供则报错。显式设置这些稠密模式专用参数时，采集模式也必须是 `dense`，避免参数被静默忽略。

保留 `--save-key`、`--quit-key`、`--pcd-fields`、`--output-dir`、`--image-ext`。稠密模式校验保存、取消和退出键实际生效的字符均非空且互不冲突，大小写视为同一热键。

`--max-pointcloud-age` 在稠密模式下用于检查每一帧进入缓存时的年龄，不用于检查整轮累加完成时第一帧的年龄。负值继续表示关闭年龄检查。

### 按帧数采集

```bash
calib-snap \
  --input-mode dual_ros \
  --source-image-topic /camera/image_raw \
  --pointcloud-topic /livox/lidar \
  --capture-mode dense \
  --accumulate-frames 50 \
  --output-dir ./data_dense
```

### 按时长采集

```bash
calib-snap \
  --input-mode camera \
  --camera-source 0 \
  --pointcloud-topic /livox/lidar \
  --capture-mode dense \
  --accumulate-seconds 3 \
  --accumulate-timeout 5 \
  --accumulate-max-mb 256 \
  --output-dir ./data_dense
```

以上命令已实现，需安装 0.1.4 或包含该功能的当前源码；0.1.3 及更早的 wheel 不包含稠密采集。

## 交互与轮次状态

| 状态 | 行为 | 转移条件 |
| --- | --- | --- |
| `IDLE` | 等待用户开始 | 按保存键且已有图像，进入 `COLLECTING` |
| `COLLECTING` | 接收本轮点云并更新进度 | 达到帧数或时长目标，进入 `READY` |
| `READY` | 点云集合已冻结，等待保存线程取走 | 保存线程取得本轮快照，进入 `SAVING` |
| `SAVING` | 保存图像和合并 PCD | 成功或失败后释放本轮数据，回到 `IDLE` |

交互规则：

1. 开始时复制当前最新图像，连同图像时间戳归属于本轮；后续图像继续采集和发布，不替换本轮图片。
2. 开始时清空本轮缓存，不把 `_latest_pointcloud` 中按键前保存的消息作为第一帧。
3. 这里的“按键后点云”指按键后进入本程序接收回调的消息。传输队列中的消息仍须通过年龄检查，但不额外要求其采样时间晚于按键时间。
4. `COLLECTING`、`READY`、`SAVING` 中再次按保存键，只报告当前状态，不重启、不排队。
5. 在 `COLLECTING` 或 `READY` 按取消键，立即释放本轮图像和点云，回到 `IDLE`，不输出文件。
6. `SAVING` 中按取消键，提示当前已开始写盘，等待本轮完成。
7. 退出或 ROS 关闭时，丢弃尚未写盘的轮次；已经进入 `SAVING` 的轮次完成保存或错误清理后再结束后台线程。

没有图像时拒绝开始并提示原因。开始时可以尚无点云，随后由首帧等待超时处理。

## 时间与结束条件

累加时长和断流超时使用注入的 `time.monotonic()` 时间值；点云年龄检查使用 ROS 当前时间与消息 `header.stamp`。两种时间不混算。测试直接推进假时钟。

定义：

- `t0`：按保存键成功启动本轮时的单调时钟时间。
- `deadline`：时长模式下的 `t0 + accumulate_seconds`。
- `silence_deadline`：没有接收过点云时为 `t0 + accumulate_timeout`；否则为最后一帧被接收的时间加超时时间。

时长窗口为 `[t0, deadline)`。回调记录的接收时间早于 `t0` 的消息不能进入本轮；每次加入点云前先检查目标截止时间和断流截止时间，按较早到期的事件结束本轮，避免后台线程调度延迟把窗口外或超时后的消息放进来。

达到目标帧数后立即关闭接收窗口。达到时长后，由后台线程结束本轮，不依赖下一帧点云到达，也不依赖摄像头读取成功。

如果断流截止时间早于目标结束时间，达到断流截止时间就取消本轮，释放缓存，记录失败原因。时长目标和断流截止时间相同时，已有接收帧则按时长目标完成，没有接收帧则失败。

时长模式结束时至少需要一帧通过接收校验的非空点云；最终写出时至少需要一个有效 XYZ 点。帧数模式未达到 N 帧时发生超时，不能作为成功采集保存。

## 点云接收规则

点云在接收回调中只做消息结构和元信息检查，不展开成 Python 点列表。

| 检查 | 处理 |
| --- | --- |
| 宽或高为零，消息不含点 | 跳过，不增加帧数，不刷新断流时间 |
| 非零时间戳对应的年龄超过 `--max-pointcloud-age` | 跳过，不增加帧数，不刷新断流时间 |
| 有时间戳的消息相对本轮上一条有时间戳的接收消息重复或倒退 | 跳过，并累计重复或乱序计数 |
| 时间戳为零 | 按接收事件计帧；不做 ROS 年龄比较，也无法据此可靠判断上游重发 |
| 首帧缺少可保存的标量 `x`、`y`、`z` 字段 | 本轮失败 |
| 后续帧的 `frame_id` 与首帧不同 | 本轮失败，避免直接混合不同坐标系 |
| 后续帧缺少已经选定的输出字段，或其类型、元素数量改变 | 本轮失败 |
| 点步长、行步长、字段偏移或数据长度不合法，或所选字段的字节区间重叠 | 本轮失败 |
| 加入这一帧后超过原始数据缓存上限 | 本轮失败，不截断、不自动降采样 |

同一轮允许全程使用空 `frame_id`，但空值与非空值之间的切换也视为变化。是否确实处于同一静止坐标系仍属于采集前提，`frame_id` 相同本身不能证明设备没有移动。

首帧按照现有 `--pcd-fields` 规则确定输出字段：缺失的非必要字段可以跳过；`x`、`y`、`z` 必须存在且 `count=1`。本轮输出字段一旦确定就固定，后续帧多出的未选字段不影响保存。

字段的字节偏移、消息字节序和行填充可以不同，只要每帧自身布局合法，输出字段的名称、数据类型和 `count` 一致。逐帧按各自布局解码，不能直接把不同布局的数据字节拼在一起。ROS `read_points()` 无法正确解码相互重叠的所选字段，因此这类布局在接收时拒绝；未选中的重叠别名字段不影响接收。

帧数目标统计通过上述接收检查的非空消息数。XYZ 的 NaN/Inf 检查在保存时逐点进行，因此一帧即使最终没有有效 XYZ 点，也已经占用一帧计数；终端接收阶段显示的是原始点数，保存结果记录实际有效点数。

缓存上限统计所有已接收消息的 `len(msg.data)` 之和，不等同于整个 Python 进程的 RSS 上限。帧数计数和原始点数均不随主循环重复读取缓存而增加。

## 模块职责与并发

保留现有单 Python 模块的发布方式，在 `calib_snap.py` 内用独立类封装轮次状态，避免将累加细节散布到两套输入循环中。

| 模块 | 职责与接口约定 |
| --- | --- |
| `DenseCaptureSession` | 管理一轮累加；提供开始、加入点云、检查截止时间并取出快照、取消、报告进度、确认保存结束的接口 |
| `CalibrationCaptureNode` | 复制起拍图像，转发 ROS 消息和热键，持有线程锁，协调后台线程与现有采集逻辑 |
| 多帧 PCD 写入函数 | 读取冻结快照，按选定字段顺序输出点和正确文件头，返回实际点数与字段信息 |
| 配对保存函数 | 分配配对文件名，写临时文件，提交输出并处理失败清理 |

`DenseCaptureSession` 不初始化 ROS、不读取真实时钟、不创建线程、不写文件。调用方显式传入接收时间和 ROS 当前时间，测试可直接验证其接口行为。

使用节点已有的互斥锁保护图像快照、轮次状态和点云消息引用。状态检查与转移在同一临界区内完成；点云解码、图像编码、文件写入和日志格式化均放在锁外。每轮快照带独立编号，后台结果只结束对应轮次。

稠密模式使用一个后台线程，兼顾截止时间检查和保存。通过事件唤醒，并以不超过 50 ms 的检查间隔处理截止时间；回调达到帧数目标时立即发出事件。实际响应允许线程调度延迟，但不延长已定义的数据接收窗口。

后台线程从 `READY` 取得唯一快照后将状态置为 `SAVING`，再在锁外写文件；同一轮只能提交一次。保存期间继续更新实时图像和最近点云，但不为下一轮缓存点云。

关闭操作须可重复调用；唤醒后台线程、释放未保存缓存，等待正在执行的保存结束并回收线程。时长和断流检查不使用 `rospy.Timer` 或 `rospy.Rate` 驱动，避免其进度依赖 ROS 仿真时钟。

## PCD 与配对文件输出

继续使用现有目录和配对文件名：

```text
data_dense/
  images/capture_<index>_<timestamp>.png
  pointclouds/capture_<index>_<timestamp>.pcd
```

多帧输出为一份扁平点集。写入 `WIDTH N`、`HEIGHT 1`、`POINTS N`，其中 N 是实际写出的有效点数；`FIELDS`、`SIZE`、`TYPE`、`COUNT` 必须与数据行对应，`COUNT` 使用字段真实的元素数量。

保持 ASCII PCD，与当前工具输出一致。按照 `--pcd-fields` 的解析顺序输出字段，并显式映射解码结果的字段顺序；不能假设 `read_points()` 的返回顺序等于请求列表顺序。多元素字段也必须正确展开，XYZ 自身仍要求标量。

保存时去掉 XYZ 任一坐标为 NaN 或 Inf 的点，保留其余选定字段的原值。最终 N 为零则本轮失败。

原始消息按帧缓存。保存分两遍流式遍历：第一遍检查解码并统计有效点数，第二遍写正确文件头和点数据。两遍复用同一字段映射和有效点判断逻辑，不创建全部点组成的巨大 Python 列表。

图像和 PCD 都先写同目录内的临时文件；图像临时文件保留可被 OpenCV 识别的图片后缀。两份文件写入成功后，通过 `os.link()` 将完整文件发布到最终路径，再清理临时路径。出现可捕获的错误则清理本轮临时文件和已提交的本轮文件，保护既有样本。最终路径已存在时不得覆盖，应重新分配文件名；输出文件系统需支持硬链接。

两份独立文件的发布不构成跨文件的原子事务；进程被强制终止或设备掉电可能留下临时文件或单边文件，本设计不作崩溃一致性保证。正常错误清理必须完整。

保存成功日志包含：轮次编号、完成原因、累加帧数、原始点数、有效点数、经过时间、点云时间戳范围、图像时间戳、`frame_id`、输出字段与两个文件路径。成功之后才更新成功采集计数。

进度日志延续现有约两秒一次的频率，至少显示状态、已收帧数及目标、原始点数、经过时间和缓存使用量。开始、取消、失败和保存完成立即记录。

## 验收与验证

| 场景 | 预期结果 |
| --- | --- |
| `dense` 缺少点云话题、未选目标、两个目标同时设置 | 启动时报参数错误 |
| 帧数非正整数，时长或超时为零、负数、NaN/Inf | 启动时报参数错误 |
| 非稠密模式显式传入稠密参数，或稠密模式热键冲突 | 启动时报参数错误 |
| 按键前已收到点云，按键后再收到三帧，每帧两个有效点 | 帧数目标为 3 时仅输出后续三帧，共 6 点 |
| 主循环多次查询同一最新点云，或收到相同非零时间戳消息 | 不重复增加累加帧数 |
| 起拍图像为 A，采集中更新为 B | 本轮保存 A，下一轮可保存 B |
| 到达时长截止后没有新点云，或摄像头持续读图失败 | 后台线程仍独立结束本轮 |
| 摄像头或 RTSP 读取返回失败，终端输入取消或退出键 | 继续处理热键，取消或退出生效 |
| 截止时间恰好收到下一帧，或后台处理晚于截止时间 | 不把窗口外的消息计入本轮，只保存一次 |
| 首帧等待或中途断流超时，重复或空帧持续到来 | 失败并清空，不将不完整轮次报告为成功 |
| 后台线程尚未处理超时，晚到点云恰好到达或超过断流截止时间 | 先结束已超时轮次，不用晚到消息刷新截止时间 |
| 一轮结束、取消或失败后重新开始 | 新轮次图像、点云、字段状态和计数独立 |
| 保存中再次按保存键，或按取消键 | 不重启、不排队、不产生重复输出 |
| 字段顺序不同于字节偏移顺序，额外字段 `count > 1` | PCD 字段声明、列顺序和列数正确 |
| 有组织点云包含行填充，或消息使用大端字节序 | 正确解码，合并输出仍为 `HEIGHT 1` |
| XYZ 含 NaN/Inf，或整轮没有有效 XYZ | 过滤无效点；总有效点数为零时失败 |
| `frame_id`、选定字段类型或元素数量中途变化 | 整轮失败，不输出混合数据 |
| 不同帧字段偏移变化，但输出字段语义一致 | 每帧按自己的布局解码，输出值正确 |
| 所选字段字节区间重叠，或仅未选中的别名字段重叠 | 前者在入缓存前失败，后者正常接收 |
| 接收时点云已经过期，或整轮时长大于最大点云年龄 | 过期帧跳过；正常累加不因首帧逐渐变老而被整体拒绝 |
| 原始缓存恰好达到上限，再收到超限帧 | 上限以内可收；超限使本轮失败且释放缓存 |
| 图像写入、PCD 写入或任一次提交失败 | 清理本轮产物，原有样本和成功计数不受影响 |
| 退出时正在采集、等待保存或正在保存 | 按状态丢弃或完成本轮，线程可正常回收 |
| 原有 `auto`、`paired`、`image` 和三种图像输入 | 默认行为与现有使用方式兼容 |

单测使用可推进的时钟和可控消息输入，不依赖真实睡眠。PCD 测试需读取生成文件，检查头部、数据行数以及各列的具体值。增加至少一条使用真实 ROS 消息与 `sensor_msgs.point_cloud2.read_points()` 的集成验证，避免仅凭消息桩掩盖布局和字段顺序问题。
